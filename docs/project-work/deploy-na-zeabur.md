# Как задеплоить проект на Zeabur

> Деплой приложения из репозитория GitHub вместе с базой PostgreSQL на Zeabur.

Zeabur собирает приложение из репозитория на GitHub, выдаёт ему публичный адрес и умеет поднимать PostgreSQL отдельным сервисом в том же проекте. На странице [Free Plan](https://zeabur.com/docs/en-US/pricing/free-plan) заявлено, что для регистрации банковская карта не нужна.

Как выбрать сервис и чем Zeabur отличается от остальных, рассказано в статье [Куда задеплоить учебный проект](kuda-deploit-proekt.md).

:::danger[Проверьте, где будет работать приложение]
Документация Zeabur не говорит, на каких серверах работают сервисы тарифа Free. Общий кластер Zeabur, на котором раньше запускали проекты, [признан устаревшим](https://zeabur.com/docs/en-US/server/shared-cluster), новые проекты на нём создавать нельзя. На [странице цен](https://zeabur.com/pricing) у тарифа Free указан один собственный сервер («1 self-managed server»), то есть сервер, купленный не у Zeabur. Серверы Zeabur стоят отдельных денег, а для карты, номера телефона или пополненного баланса есть шаг проверки аккаунта при создании первого проекта ([быстрый старт](https://zeabur.com/docs/en-US/get-started/quick-start)). ## Что понадобится

Нужен аккаунт на [GitHub](https://github.com/) и репозиторий с приложением. Вход на Zeabur через GitHub описан в разделе ниже.

## Подготовьте приложение

Общие требования к приложению описаны в статье [Куда задеплоить учебный проект](kuda-deploit-proekt.md).

Для сервисов из Git-репозитория Zeabur сам подставляет переменную `PORT` со значением `8080`, настраивать её не нужно ([переменные окружения](https://zeabur.com/docs/en-US/deploy/config/environment-variables)). Если в репозитории есть `Dockerfile`, порт берётся из него, а если порт не указан, используется `8080` ([домены](https://zeabur.com/docs/en-US/deploy/networking/public-networking)). Сервер приложения читает порт из `PORT` и слушает адрес `0.0.0.0`.

Если в корне репозитория лежит `Dockerfile`, Zeabur собирает образ по нему, и в `Dockerfile` должен быть открыт порт приложения через `EXPOSE` ([Dockerfile](https://zeabur.com/docs/en-US/deploy/methods/dockerfile)). Без `Dockerfile` Zeabur сам определяет язык и фреймворк ([быстрый старт](https://zeabur.com/docs/en-US/get-started/quick-start)).

## Подключите базу PostgreSQL

В документации PostgreSQL ставится из каталога шаблонов: в панели выберите **Template**, найдите `PostgreSQL` и выберите официальный образ, деплой начнётся сразу ([PostgreSQL](https://zeabur.com/docs/en-US/marketplace/postgresql)). На странице тарифов ограничения для баз на Free не указаны. Автоматические бэкапы и импорт баз начинаются с тарифа Dev ([Free Plan](https://zeabur.com/docs/en-US/pricing/free-plan)).

Приложение получает адрес и пароль базы через переменные окружения. Сервис PostgreSQL публикует переменные `POSTGRES_CONNECTION_STRING`, `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_USERNAME` и `POSTGRES_PASSWORD`. Имя базы страница не называет, его показывает вкладка **Instruction** у сервиса PostgreSQL. На переменные ссылаются записью `${ИМЯ}` в значении переменной приложения. Переменные приложения лежат во вкладке **Variables** ([PostgreSQL](https://zeabur.com/docs/en-US/marketplace/postgresql), [переменные окружения](https://zeabur.com/docs/en-US/deploy/config/environment-variables)).

Многие библиотеки для Node.js и Python принимают адрес базы как есть. Заведите в приложении переменную `DATABASE_URL` со значением `${POSTGRES_CONNECTION_STRING}`.
{/* TODO: проверить в интерфейсе, что формат строки подходит библиотеке из учебного проекта */}

Если в проекте несколько баз PostgreSQL, ссылки на переменные могут срабатывать неверно. Тогда скопируйте внутренний адрес и порт из вкладки **Networking** сервиса базы ([PostgreSQL](https://zeabur.com/docs/en-US/marketplace/postgresql)). Внутренний адрес вида `postgresql.zeabur.internal` работает только между сервисами одного проекта ([частная сеть](https://zeabur.com/docs/en-US/deploy/networking/private-networking)).

Java-приложению нужен адрес в формате JDBC, и его собирают из отдельных переменных. Имя базы подставьте из вкладки **Instruction**.

```text
jdbc:postgresql://${POSTGRES_HOST}:${POSTGRES_PORT}/ИМЯ_БАЗЫ?user=${POSTGRES_USERNAME}&password=${POSTGRES_PASSWORD}
```

## Java-приложение

Если в корне репозитория есть `Dockerfile`, Zeabur собирает проект по нему. Без него Zeabur поддерживает Java-проекты на Maven и Gradle. Он ищет готовый JAR в `target/*.jar` для Maven и в `build/libs/*.jar` для Gradle. Версия JDK по умолчанию 17, её задают в `pom.xml` или `build.gradle`. Команду запуска можно переопределить полем `javaArgs` в `zbpack.json`, тогда в неё нужно вписать `-jar` и путь к JAR самому ([Java](https://zeabur.com/docs/en-US/guides/java)).

Для Spring Boot порт передают в `javaArgs` как `-Dserver.port=$PORT`. Приложению на Javalin порт нужен из переменной `PORT`, как в блоге из статьи про Railway.

```java
String port = System.getenv().getOrDefault("PORT", "3000");
```

## Ограничения бесплатного тарифа

Документация называет такие ограничения Free ([Free Plan](https://zeabur.com/docs/en-US/pricing/free-plan), [цены](https://zeabur.com/pricing)).

- Сервисы засыпают после периода без запросов и просыпаются на следующем запросе, пробуждение занимает несколько секунд.
- SLA нет, почты через Zeabur Email нет, автоматических бэкапов и импорта баз нет.
- Журналы хранятся 48 часов, файл загружается размером до 50 МБ.
- Домены Free не покупаются, а адрес `zeabur.app` выдаётся бесплатно.

Лимиты памяти, процессора и числа сервисов на страницах тарифов не названы. Сборка идёт на машине 2C4G независимо от запуска сервиса.

Условия использования Zeabur не называют ограничений по странам и регионам. В них перечислены запреты общего вида, например нарушение законов, включая экспортный контроль ([Terms of Service](https://zeabur.com/docs/en-US/terms-of-service)). Бесплатные планы без оплаты ограничены некоммерческим использованием ([Fair Use Guidelines](https://zeabur.com/docs/en-US/compliance/fair-use-guidelines)), а учебный проект под это подходит. Нарушение условий даёт Zeabur право прекратить доступ к сервису.

## Если что-то пошло не так

Сначала откройте журналы сервиса, причина почти всегда написана там.

- **Деплой не стартует, Zeabur просит сервер или оплату.** Скорее всего, на Free нет серверов Zeabur, см. плашку в начале статьи. Напишите в [поддержку](https://zeabur.com/support).
- **Сборка прошла, а адрес не открывается.** Проверьте, что сервер слушает `0.0.0.0` и порт из `PORT`, а в `Dockerfile` порт открыт через `EXPOSE`.
- **Приложение долго открывается после паузы.** Сервис заснул, это поведение Free. Откройте адрес заранее перед показом наставнику.
- **Приложение не подключается к базе.** Проверьте имя переменной, ссылку `${...}` и имя базы во вкладке **Instruction**.
