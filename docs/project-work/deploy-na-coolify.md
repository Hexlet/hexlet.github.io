# Как задеплоить проект на свой сервер с Coolify

> Деплой приложения вместе с базой PostgreSQL на свой сервер через веб-панель.

{/* TODO: проверить в интерфейсе. Статья написана по официальной документации, шаги вживую не проходились. */}

[Coolify](https://coolify.io/docs/core/what-is-coolify) это платформа с веб-панелью, которую вы ставите на свой сервер. В панели вы подключаете репозиторий GitHub, создаёте приложение и базу и запускаете деплой кнопкой. Сборкой и запуском контейнеров Coolify занимается сама.

Этот вариант подходит, когда нужен собственный сервер. Сервер платный и арендуется у провайдера на ваш выбор, подойдёт любой с Ubuntu. Взамен у вас нет лимитов бесплатных тарифов, а приложение работает постоянно и не засыпает. Как выбрать между сервисами, рассказано в статье [Куда задеплоить учебный проект](kuda-deploit-proekt.md). Если вам привычнее командная строка и `git push`, посмотрите вариант с Dokku в статье [Как задеплоить проект на свой сервер с Dokku](deploy-na-dokku.md).

## Что понадобится

Нужен VPS с чистой операционной системой. По [документации Coolify](https://coolify.io/docs/get-started/installation) для работы нужны 2 ядра CPU, 2 ГБ памяти и 10 ГБ диска. На меньшей машине Coolify запускается, но так делать не советуют. Подходят Debian и Ubuntu, документация рекомендует Ubuntu LTS. Архитектура amd64 или arm64.

Ещё понадобятся доступ к серверу по SSH с правами root или пользователя с sudo, аккаунт на [GitHub](https://github.com/) и репозиторий с приложением. Домен необязателен, Coolify умеет выдавать адрес с IP-адресом сервера.

## Подготовьте приложение

Общие требования к приложению описаны в статье [Куда задеплоить учебный проект](kuda-deploit-proekt.md). Приложение должно слушать порт и адрес `0.0.0.0`. [Документация Coolify](https://coolify.io/docs/applications/configuration/environment-variables) сама задаёт переменную `PORT` значением первого открытого порта, а `HOST` значением `0.0.0.0`, если вы их не задали. Внутренний порт, на котором слушает приложение, вы указываете при создании ресурса.

## Установите Coolify

Подключитесь к серверу по SSH под root и выполните однострочный скрипт установки из [документации](https://coolify.io/docs/get-started/installation).

```sh
curl -fsSL https://cdn.coollabs.io/coolify/install.sh | bash
```

Документация просит открыть в файрволе порты, которые нужны Coolify, и называет порт панели 8000. Полный список портов смотрите на странице [Firewall](https://coolify.io/docs/core/infrastructure/servers/firewall). Для приложений понадобятся порты 80 и 443.

## Создайте администратора

Когда установка закончится, откройте в браузере адрес `http://<IP-сервера>:8000` и создайте учётную запись администратора. Сделайте это сразу. Документация предупреждает, что любой, кто первым дойдёт до страницы регистрации, станет администратором. Если вместо формы вы видите сообщение «Setup window closed», выполните на сервере `docker restart coolify` и обновите страницу.

## Подключите репозиторий

Есть два способа, и выбор зависит от репозитория.

**Публичный репозиторий.** Ничего настраивать заранее не нужно. В проекте нажмите **+ New**, выберите **Public Repository**, выберите сервер (при самостоятельной установке он называется **localhost**) и вставьте ссылку на репозиторий. По [документации](https://coolify.io/docs/applications/sources/github/public-repository) без указания ветки берётся `main`. Нажмите **Check Repository**.

**Приватный репозиторий.** Нужен GitHub App. Откройте **Sources**, нажмите **New source** и выберите **GitHub App**, затем следуйте [инструкции Coolify](https://coolify.io/docs/applications/sources/github/app) до кнопки **Register with GitHub**. На GitHub выдайте доступ только к нужным репозиториям, **Only select repositories**. После этого приложение создаётся из пункта **Private Repository (with GitHub App)**.

Автоматический деплой по пушу в GitHub App требует, чтобы GitHub достучался до панели по публичному адресу. На простом адресе с IP и портом 8000 этот способ может не заработать, тогда деплой запускается вручную кнопкой **Deploy**.

## Создайте приложение

После **Check Repository** выберите **Build pack**, внутренний порт и базовую папку, при необходимости. Coolify поддерживает [несколько вариантов сборки](https://coolify.io/docs/applications/builds/overview), среди них Nixpacks и Dockerfile.

Nixpacks сам определяет язык и фреймворк по коду и составляет инструкции сборки. Он подходит, если проект следует обычным соглашениям языка. В **General** Coolify показывает определённые команды **Install Command**, **Build Command** и **Start Command**, и их можно изменить. Для Node.js версию Nixpacks берёт из `engines.node`, `.nvmrc` или `.node-version`.

Если в репозитории лежит `Dockerfile`, выберите сборку по нему. Образ описываете вы сами, и это самый предсказуемый вариант для Java.

## Создайте базу и передайте строку подключения

Базу создаёт отдельный ресурс в том же проекте. По [документации](https://coolify.io/docs/databases/postgresql) откройте проект и окружение, нажмите **New Resource**, в разделе **Databases** выберите **PostgreSQL**, затем сервер и сеть Docker. Образ оставьте стандартный. Нажмите **Start** и дождитесь, пока контейнер станет здоровым.

В **General** у базы Coolify показывает **Postgres URL (internal)**. Приложения из той же сети используют именно его, он выглядит так.

```text
postgres://<пользователь>:<пароль>@<контейнер-базы>:5432/<база>
```

Публичный доступ к базе по умолчанию выключен, и это правильно, для учебного проекта он не нужен.

### Переменные окружения

Откройте приложение, выберите **Environment Variables**, нажмите **Add**, введите **Name** и **Value** и нажмите **Add variable**. Заведите `DATABASE_URL` со значением из **Postgres URL (internal)**. Так же задаются любые другие настройки приложения.

После сохранения переменных перезапустите приложение. Если менялись значения, нужные при сборке, нужен новый деплой кнопкой **Redeploy**. Если только значения времени выполнения, хватит кнопки **Restart**.

### Java и JDBC

Java-приложению нужен адрес в формате JDBC. Coolify отдаёт URL вида `postgres://`, поэтому JDBC-адрес собирается из его частей. Заведите переменную, которую читает приложение, например `JDBC_DATABASE_URL`, и подставьте в неё свои значения из страницы базы.

```text
jdbc:postgresql://<контейнер-базы>:5432/<база>?user=<пользователь>&password=<пароль>
```

## Запустите деплой

В конфигурации приложения нажмите **Deploy**. Ход сборки и запуска виден в **Deployment Logs**, там же можно убедиться, что взят нужный репозиторий, ветка и коммит. Ошибки сборки появляются именно в этом журнале.

Когда контейнер запущен, смотрите **Runtime Logs**. Там вывод самого приложения, то есть исключения, падения и ошибки подключения к базе.

После изменений в настройках нужен **Redeploy**, сохранение настроек работающий контейнер не заменяет.

## Получите адрес

Если в настройках сервера не задан **Wildcard Domain**, Coolify [создаёт адрес](https://coolify.io/docs/core/networking/domains) из IP-адреса сервера и сервиса sslip.io, DNS настраивать не нужно. Он выглядит как `http://<uuid>.<IP-сервера>.sslip.io`. Адрес открывается по HTTP. Документация предупреждает, что менять его на HTTPS не стоит, потому что Let's Encrypt ограничивает частоту выдачи сертификатов для общей зоны sslip.io.

Если порт приложения не определился, укажите его в адресе, например `http://адрес:3000`, или в поле **Port**. Если у вас свой домен, создайте A-запись на IP сервера и выберите протокол **https**, Coolify сама получит сертификат. Для этого порты 80 и 443 должны доходить до сервера.

После смены домена перезапустите приложение, чтобы прокси подхватил настройку.

## Безопасность сервера

В документации Coolify по установке про защиту сервера сказано только две вещи. Откройте в файрволе нужные порты, а первую учётную запись создайте сразу после установки, пока страницу регистрации не нашёл кто-то другой. Сверх этого рекомендаций для начинающих там нет.

## Если что-то пошло не так

Начните с **Deployment Logs** при ошибках сборки и с **Runtime Logs** при ошибках запуска.

- **Панель на порту 8000 не открывается.** Порт закрыт файрволом на сервере или у провайдера. Откройте его, как описано на странице [Firewall](https://coolify.io/docs/core/infrastructure/servers/firewall).
- **Вместо регистрации «Setup window closed».** Выполните на сервере `docker restart coolify` и обновите страницу.
- **Адрес не открывается или показывает ошибку шлюза.** Внутренний порт в настройках не совпадает с портом, на котором слушает приложение. Проверьте и то, что приложение слушает `0.0.0.0`.
- **Приложение не подключается к базе.** Используйте **Postgres URL (internal)**, а не публичный адрес. Приложение и база должны быть в одной сети Docker.
- **Сборка падает, а в журнале Nixpacks определил не тот язык.** Проверьте базовую папку, лишние файлы блокировок в репозитории или выберите сборку по `Dockerfile`.
