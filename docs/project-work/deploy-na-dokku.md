# Как задеплоить проект на свой сервер с Dokku

> Деплой приложения вместе с базой PostgreSQL на свой сервер командой git push.

{/* TODO: проверить на сервере. Статья написана по официальной документации, шаги вживую не проходились. */}

[Dokku](https://dokku.com/) это небольшая платформа для одного сервера, которая работает по образцу Heroku. Вы ставите её на арендованный VPS, добавляете в репозиторий ещё один git remote и отправляете код командой `git push`. Dokku сама собирает приложение и запускает его в контейнере.

Этот вариант подходит, когда нужен собственный сервер. Сервер платный и арендуется у провайдера на ваш выбор, подойдёт любой с Ubuntu. Взамен у вас нет лимитов бесплатных тарифов, а приложение работает постоянно и не засыпает. Как выбрать между сервисами, рассказано в статье [Куда задеплоить учебный проект](kuda-deploit-proekt.md). Если вам удобнее веб-панель с кнопками, посмотрите вариант с Coolify в статье [Как задеплоить проект на свой сервер с Coolify](deploy-na-coolify.md). Dokku управляется из командной строки.

## Что понадобится

Нужен VPS с чистой операционной системой. По [документации Dokku](https://dokku.com/docs/getting-started/installation/) подходят Ubuntu 22.04, 24.04 или 26.04 и Debian 11 и новее, архитектура AMD64 или arm64. Памяти нужен 1 ГБ, а если её меньше, документация советует добавить swap.

Ещё понадобятся доступ к серверу по SSH с правами root и репозиторий с приложением на вашем компьютере. Домен необязателен, приложение откроется и по адресу с IP-адресом сервера.

## Подготовьте приложение

Общие требования к приложению описаны в статье [Куда задеплоить учебный проект](kuda-deploit-proekt.md). Для Dokku важно, что приложение читает порт из переменной `PORT`. [Документация](https://dokku.com/docs/networking/port-management/) предупреждает, что Dokku обычно задаёт порт 5000, но не гарантирует это, поэтому значение зашивать нельзя. Задавать `PORT` вручную тоже не нужно, Dokku делает это сама через сопоставление портов.

Если в корне репозитория лежит `Dockerfile`, Dokku [собирает образ по нему](https://dokku.com/docs/deployment/builders/dockerfiles/), но только когда не определились сборщики Herokuish и Cloud Native Buildpacks. Для приложений на Node.js и других языках без `Dockerfile` Dokku использует [buildpacks](https://dokku.com/docs/deployment/application-deployment/) через Herokuish, это способ по умолчанию.

## Установите Dokku

Подключитесь к серверу по SSH под root и выполните команды установки. Версия в них взята со [страницы установки](https://dokku.com/docs/getting-started/installation/) на 11 ноября 2026 года, перед установкой сверьтесь со страницей, на ней может быть более новая.

```sh
wget -NP . https://dokku.com/install/v0.38.34/bootstrap.sh
sudo DOKKU_TAG=v0.38.34 bash bootstrap.sh
```

Установка занимает около 10 минут, по документации не меньше 5 минут. Скрипт сам добавляет SSH-ключи из `~/.ssh/authorized_keys` пользователя root и задаёт IP-адрес сервера как глобальный домен, если они не настроены.

Если нужно добавить ключ вручную, выполните на сервере эту команду. Она берёт ключи из `authorized_keys` и регистрирует их под именем `admin`.

```sh
cat ~/.ssh/authorized_keys | sudo dokku ssh-keys:add admin
```

## Создайте приложение

Команды `dokku` ниже выполняются на сервере. Создайте приложение, имя возьмите любое, например по названию проекта.

```sh
dokku apps:create myapp
```

## Создайте базу и передайте строку подключения

База PostgreSQL ставится официальным [плагином dokku-postgres](https://github.com/dokku/dokku-postgres). Ему нужна Dokku версии 0.35 или новее, это выполняется для текущей версии. Установите плагин, создайте сервис базы и свяжите его с приложением.

```sh
sudo dokku plugin:install https://github.com/dokku/dokku-postgres.git --name postgres
dokku postgres:create mydb
dokku postgres:link mydb myapp
```

Команда `postgres:link` задаёт приложению переменную `DATABASE_URL` в формате `postgres://`, а потом перезапускает приложение. Адрес базы внутри сети Docker выглядит так, как показано в документации плагина.

```text
postgres://:SOME_PASSWORD@dokku-postgres-mydb:5432
```

Полную строку с именем пользователя и базой покажет команда `dokku postgres:info mydb`, а ключ `--dsn` выводит только строку подключения. Многие библиотеки Node.js и Python принимают `DATABASE_URL` как есть.

### Java и JDBC

Java-приложению нужен адрес в формате JDBC. Плагин умеет задавать его сам, для этого `link` выполняется с флагом `--jdbc`. Он добавляет переменные `JDBC_DATABASE_URL`, `JDBC_DATABASE_USERNAME` и `JDBC_DATABASE_PASSWORD` к `DATABASE_URL`. Если приложение уже связано с базой, сначала разорвите связь командой `dokku postgres:unlink mydb myapp`, а потом свяжите заново.

```sh
dokku postgres:link mydb myapp --jdbc
```

Читайте адрес из `JDBC_DATABASE_URL` в коде приложения, как это сделано в учебном блоге на Javalin.

## Запустите деплой

Команды этого раздела выполняются на вашем компьютере, в каталоге репозитория. Добавьте remote. Имя пользователя в нём должно быть `dokku`, иначе push не пройдёт, а `1.2.3.4` замените на адрес вашего сервера.

```sh
git remote add dokku dokku@1.2.3.4:myapp
git push dokku main
```

Dokku принимает код, собирает приложение и запускает его. Сборка занимает несколько минут, ход сборки виден прямо в терминале.

### Порт для приложения с Dockerfile

Если приложение собирается по `Dockerfile` и в нём есть `EXPOSE`, Dokku [проксирует этот порт](https://dokku.com/docs/networking/port-management/) наружу под тем же номером. Чтобы приложение открывалось на обычном порту 80, добавьте сопоставление командой `ports:set`. В примере приложение слушает порт 3000.

```sh
dokku ports:set myapp http:80:3000
```

Если приложение раньше собиралось buildpacks и порты уже настраивались, перед деплоем по Dockerfile выполните `dokku ports:clear myapp`.

## Получите адрес

Приложение открывается по адресу `<имя-приложения>.<глобальный-домен>`. Глобальный домен, который скрипт установки задаёт по IP-адресу, поддерживает поддомены не всегда. По [документации](https://dokku.com/docs/getting-started/installation/) для поддоменов добавьте к IP-адресу `.sslip.io`. Такой адрес работает без настройки DNS, сервис sslip.io сам возвращает IP, который записан в имени. Задайте его командой на сервере.

```sh
dokku domains:set-global 1.2.3.4.sslip.io
```

Свой домен тоже подойдёт. Создайте у регистратора A-запись на IP сервера и задайте её тем же способом, `dokku domains:set-global ваш-домен`. Для поддоменов приложений нужна wildcard-запись `*.ваш-домен`.

### HTTPS

HTTPS по умолчанию выключен. Для наставника хватит адреса по HTTP. Если у вас свой домен, сертификат выдаёт плагин [dokku-letsencrypt](https://github.com/dokku/dokku-letsencrypt). Приложение уже должно быть задеплоено и открываться по HTTP через порт 80, а домен должен указывать на сервер.

```sh
sudo dokku plugin:install https://github.com/dokku/dokku-letsencrypt.git
dokku letsencrypt:set myapp email you@example.com
dokku letsencrypt:enable myapp
dokku letsencrypt:cron-job --add
```

Последняя команда включает автоматическое продление сертификата.

Для адресов sslip.io сертификаты лучше не запрашивать, HTTPS настраивается для своего домена.

## Логи и память

Журнал приложения показывает команда `dokku logs`. Ключ `-t` держит поток открытым и печатает новые строки.

```sh
dokku logs myapp -t
```

Память ограничивается командой `resource:limit`, число в мегабайтах. Для применения нужны пересборка или новый деплой.

```sh
dokku resource:limit --memory 512 myapp
```

Если сборка падает с нехваткой памяти на сервере в 1 ГБ, добавьте swap. Об этом говорит и документация Dokku.

## Если что-то пошло не так

Сначала посмотрите журнал приложения командой `dokku logs myapp`, причина обычно написана там.

- **Push отклонён, в ответе `Permission denied (publickey)`.** Ваш ключ не добавлен в Dokku, повторите команду `dokku ssh-keys:add` из раздела об установке. Проверьте и то, что в remote пользователь `dokku`, а не root.
- **Приложение собрано, а адрес не открывается.** Приложение слушает не тот порт или адрес `127.0.0.1`. Проверьте, что сервер читает `PORT` и слушает `0.0.0.0`, а для Dockerfile проверьте `ports:set`.
- **Приложение не подключается к базе.** Проверьте, что `postgres:link` выполнен, а в `dokku config myapp` есть `DATABASE_URL`. У Java проверьте `JDBC_DATABASE_URL`.
- **Сборка падает без понятной причины.** Часто виновата нехватка памяти на сервере, добавьте swap.
