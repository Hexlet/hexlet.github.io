# Как задеплоить проект на Render

> Деплой учебного проекта с базой PostgreSQL на бесплатный тариф Render.

Render собирает приложение из репозитория на GitHub, запускает его и выдаёт адрес вида `<имя>.onrender.com`. На нём построены уроки о деплое в курсах Хекслета. Инструкция проверена 11 ноября 2026 года на учебном блоге [java-javalin-blog](https://github.com/hexlet-components/java-javalin-blog) с базой PostgreSQL на бесплатном тарифе.

У части студентов из России Render открывается только через VPN или просит привязать банковскую карту. Если вы столкнулись с этим, задеплойте проект [на Railway](deploy-na-railway.md).

## Что понадобится

Нужен аккаунт на [GitHub](https://github.com/) и репозиторий с приложением. В Render удобнее всего войти через GitHub кнопкой **Continue with GitHub**.

## Подготовьте приложение

Render передаёт приложению порт в переменной окружения `PORT`, по умолчанию это `10000`. Сервер должен слушать этот порт на адресе `0.0.0.0` ([требование Render](https://render.com/docs/web-services#port-binding)). Если сервер слушает `127.0.0.1` или фиксированный порт, Render не дождётся ответа и деплой не завершится.

```java
String port = System.getenv().getOrDefault("PORT", "3000");
```

Для Node.js, Python, Ruby, Go, Rust и Elixir у Render есть готовая среда выполнения. В ней вы указываете команду сборки (**Build Command**) и команду запуска (**Start Command**), а версию языка можно закрепить переменной окружения, например `NODE_VERSION=24` для Node.js. Для Java, PHP и .NET готовой среды нет ([список сред](https://render.com/docs/native-runtimes)), такие приложения запускаются по `Dockerfile` из корня репозитория.

Блог на Javalin собирается так. Образ ставит JDK и Gradle, выполняет `gradle installDist` и запускает собранное приложение. Полный файл лежит в [репозитории блога](https://github.com/hexlet-components/java-javalin-blog/blob/main/Dockerfile).

```dockerfile
RUN gradle installDist

CMD ["./build/install/java-javalin-blog/bin/java-javalin-blog"]
```

Проверьте локально, что приложение собирается и запускается теми же командами. Если не работает на вашем компьютере, на Render тоже не заработает.

## Создайте базу данных

Если приложению нужна база, создайте её первой. Нажмите **New** вверху страницы и выберите **Postgres**.

![Меню New в Render с пунктами Web Service и Postgres](/img/docs/img-231--render-new-menu.png)

Задайте имя базы в поле **Name**, остальные поля до региона можно не заполнять. Запомните регион (**Region**), сервис приложения нужно будет создать в том же регионе.

Ниже, в разделе **Compute**, по умолчанию выбран платный тариф. Отметьте строку **$0 / month** с пометкой Free. Render предупредит, что бесплатная база удаляется через 30 дней.

![Раздел Compute при создании базы, выбрана строка $0 в месяц с пометкой Free и предупреждением о 30 днях](/img/docs/img-232--render-postgres-free.png)

Нажмите **Create database**. Через минуту-две в разделе **Connections** появятся параметры подключения.

![Раздел Connections базы, имя хоста, порт, имя базы и пользователь, пароль и адреса ещё готовятся](/img/docs/img-233--render-postgres-connections.png)

Приложению на Render нужен **Internal Database URL**, он работает внутри сети Render в том же регионе. **External Database URL** нужен для подключения с вашего компьютера, например через `psql`.

## Создайте веб-сервис

Нажмите **New** и выберите **Web Service**. На вкладке **Git Provider** выберите свой репозиторий, при первом входе Render попросит доступ к GitHub. Вкладка **Public Git Repository** принимает адрес любого публичного репозитория, но тогда Render не будет сам пересобирать приложение после пуша.

Render определяет язык по файлам репозитория. Если в корне лежит `Dockerfile`, в поле **Language** будет стоять Docker. Регион выберите тот же, что у базы.

![Поля Language, Branch и Region при создании веб-сервиса, выбраны Docker, ветка main и регион Frankfurt](/img/docs/img-234--render-web-docker-region.png)

В разделе **Compute** по умолчанию тоже выбран платный тариф. Отметьте **$0 / month** с пометкой Free.

![Раздел Compute при создании веб-сервиса, выбрана строка $0 в месяц с пометкой Free](/img/docs/img-235--render-web-free.png)

## Передайте приложению строку подключения

Render сам не передаёт приложению параметры базы, строку подключения нужно добавить в переменные окружения. Это можно сделать в разделе **Environment Variables** при создании сервиса или позже во вкладке **Environment** сервиса.

Приложения на Node.js, Python и Rails обычно читают адрес из переменной `DATABASE_URL`. Скопируйте в неё Internal Database URL целиком.

Java-приложению нужен адрес в формате JDBC, и он отличается от Internal Database URL. В JDBC логин и пароль передаются параметрами, а порт пишется явно.

```text
Internal Database URL  postgresql://USER:PASSWORD@HOST/DATABASE
JDBC                   jdbc:postgresql://HOST:5432/DATABASE?user=USER&password=PASSWORD
```

Блог на Javalin читает адрес из переменной `JDBC_DATABASE_URL`. Без неё он запускается на базе H2 в памяти, и данные пропадают при каждом перезапуске.

![Вкладка Environment сервиса, переменная JDBC_DATABASE_URL со скрытым значением](/img/docs/img-236--render-env-variable.png)

:::danger[Не добавляйте jdbc: к Internal Database URL]
Строка `jdbc:postgresql://USER:PASSWORD@HOST/DATABASE` выглядит правильной, но драйвер PostgreSQL принимает часть до `@` за адрес хоста. Приложение падает с ошибкой `JDBC URL invalid port number` и `No suitable driver`, а строка подключения вместе с паролем попадает в журнал Render. Если это случилось с настоящей базой, смените пароль.
:::

## Запустите деплой

Нажмите **Deploy web service**. Render скачает код, соберёт приложение и запустит его. Сборка блога на Javalin заняла меньше двух минут. Когда деплой закончится, в статусе появится **Deploy succeeded** с пометкой Live.

![Страница деплоя, статус Deploy succeeded, Live, длительность 1 минута 44 секунды и журнал запуска Javalin](/img/docs/img-237--render-deploy-live.png)

Журнал приложения открывается во вкладке **Logs**. По нему видно, к какой базе подключилось приложение. На снимке поиск по `HikariPool` показывает первый запуск на H2 и запуск после добавления `JDBC_DATABASE_URL`, когда пул соединений подключился к PostgreSQL.

![Журнал Render с поиском HikariPool, сначала подключение jdbc:h2:mem:blog, затем org.postgresql.jdbc.PgConnection](/img/docs/img-238--render-postgres-logs.png)

Адрес приложения указан на странице сервиса под его названием. Откройте его и проверьте, что приложение работает и сохраняет данные.

![Блог на Javalin, открытый по адресу на Render, со статьёй из базы PostgreSQL](/img/docs/img-239--render-java-blog.png)

После каждого пуша в подключённую ветку Render пересобирает приложение сам. Если сборка или запуск новой версии упали, Render оставляет работать предыдущую.

## Ограничения бесплатного тарифа

Бесплатный веб-сервис получает 0,1 CPU и 512 МБ памяти, а на все бесплатные сервисы рабочего пространства даётся 750 часов в месяц ([условия Free](https://render.com/docs/free)). Сервис засыпает через 15 минут без запросов. Первый запрос после сна ждёт запуска около минуты, Render показывает в это время страницу загрузки. Графики памяти и процессора на Free недоступны.

Бесплатная база PostgreSQL занимает до 1 ГБ и живёт 30 дней. После этого даётся 14 дней на переход на платный тариф, затем база удаляется вместе с данными. В одном рабочем пространстве может быть только одна бесплатная база, поэтому перед новым проектом удалите старую.

С бесплатного сервиса нельзя отправлять почту напрямую, исходящие соединения на порты 25, 465 и 587 закрыты.

## Если что-то пошло не так

Сначала откройте журнал деплоя, причина почти всегда написана там.

- **Деплой упал со строкой `Exited with status 1`.** Приложение завершилось при запуске. Ошибка написана в журнале выше этой строки.
- **`JDBC URL invalid port number` и `No suitable driver`.** Адрес базы записан не в формате JDBC. Соберите его по шаблону из раздела про строку подключения.
- **Сборка прошла, а деплой не завершается.** Сервер слушает не тот порт или адрес. Проверьте `0.0.0.0` и `process.env.PORT` или его аналог в вашем языке.
- **Приложение не подключается к базе.** Проверьте, что сервис и база созданы в одном регионе и что используется Internal Database URL.
- **Данные пропадают после перезапуска.** Приложение работает на базе в памяти или в файле. Проверьте, что переменная с адресом PostgreSQL задана и приложение её читает.
