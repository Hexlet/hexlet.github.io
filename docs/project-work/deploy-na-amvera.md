# Как задеплоить проект на Amvera

> Деплой учебного проекта с базой PostgreSQL на платный сервис Amvera Cloud.

Amvera Cloud собирает приложение из репозитория, запускает его в контейнере и выдаёт бесплатный адрес в домене `amvera.tech`. Бесплатного тарифа у сервиса нет, платят по времени работы приложения и базы, поэтому перед началом прочитайте раздел про тарифы.

Как выбрать сервис и что подготовить в приложении, рассказано в статье [Куда задеплоить учебный проект](kuda-deploit-proekt.md).

## Что понадобится

Нужен аккаунт в личном кабинете [cloud.amvera.ru](https://cloud.amvera.ru) и положительный баланс, чтобы создать приложение и базу. Способы пополнения описаны на странице [Пополнение счёта](https://docs.amvera.ru/general/topup.html). Для кода подойдёт любой из двух путей. Можно отправить его в репозиторий Amvera командой `git push` или подключить репозиторий на GitHub.

## Подготовьте приложение

Общие требования к приложению описаны в статье [Куда задеплоить учебный проект](kuda-deploit-proekt.md). У Amvera есть одно важное отличие от Render и Railway. Сервис не передаёт приложению порт в переменной `PORT`. Вы сами решаете, какой порт слушает приложение, и записываете его в параметр `containerPort` файла настроек. По умолчанию он равен `80`. Приложение по-прежнему должно слушать адрес `0.0.0.0`, иначе снаружи оно недоступно и сервис отвечает ошибкой 502 ([частые ошибки 502 и 503](https://docs.amvera.ru/general/FAQ/502-503-error.html)).

### Файл настроек amvera.yml

Настройки сборки и запуска лежат в файле `amvera.yml` или `amvera.yaml` в корне репозитория ([файл конфигурации](https://docs.amvera.ru/applications/configuration/config-file.html)). Если его нет, Amvera ищет `Dockerfile`, а если нет и его, сборка падает. Файл состоит из разделов `meta` (окружение и версия), `build` (сборка) и `run` (запуск). Составить его можно на [manifest.amvera.ru](https://manifest.amvera.ru/) или создать в разделе «Конфигурация» приложения.

{/* TODO: проверить в интерфейсе раздел «Конфигурация» */}

Для популярных языков у Amvera есть готовые окружения, и свой `Dockerfile` не нужен.

**Node.js.** Окружение `node` с менеджером `npm`. Сервис выполняет `npm install` и любые команды из `build.additionalCommands`, а запускает скрипт из `run.scriptName` или команду из `run.command` ([Node.js Server](https://docs.amvera.ru/applications/environments/nodejs-server.html)).

```yaml
meta:
  environment: node
  toolchain:
    name: npm
    version: 18

build:
  additionalCommands: npm run build

run:
  command: npm run start
  containerPort: 3000
```

Версия Node.js становится тегом образа `node:<версия>`, поэтому берите ту, на которой приложение работает у вас.

**Python.** Окружение `python` с менеджером `pip`. Зависимости берутся из `requirements.txt` в корне, а запуск задаёт `run.scriptName` или `run.command`. Порт в команде запуска должен совпадать с `containerPort` ([Python Pip](https://docs.amvera.ru/applications/environments/python-pip.html)).

```yaml
meta:
  environment: python
  toolchain:
    name: pip
    version: 3.10

run:
  command: gunicorn --bind 0.0.0.0:5000 app:app
  containerPort: 5000
```

**Java.** Окружения `jvm` с `gradle` или `maven`. Сервис собирает проект и запускает JAR-файл по имени из `run.jarName` ([JVM Gradle](https://docs.amvera.ru/applications/environments/jvm-gradle.html)). Для Gradle сборка идёт командой `gradle build`, а файлы из `build/libs` копируются в приложение. Блог на Javalin собирается командой `gradle installDist` и не даёт готового JAR, поэтому для него проще взять `Dockerfile`, как в статье про [Render](deploy-na-render.md).

```yaml
meta:
  environment: jvm
  toolchain:
    name: gradle
    version: 21

run:
  jarName: app.jar
  containerPort: 8080
```

{/* TODO: проверить в интерфейсе версию JDK, которую принимает окружение jvm. В документации версия 11, для LTS 21 нужна проверка */}

**Rails.** Страница [Ruby (Rails)](https://docs.amvera.ru/applications/environments/ruby-bundle.html) описывает окружение `ruby` с `bundle` и запуск главного скрипта через `run.mainScript`. Настроек именно для Rails на ней нет, поэтому для Rails-проекта надёжнее взять `Dockerfile`.

**PHP.** Готового окружения для PHP среди поддерживаемых в документации нет ([поддерживаемые окружения](https://docs.amvera.ru/applications/supported-env.html)). PHP-приложение запускается по `Dockerfile`.

### Dockerfile

Приложение можно развернуть, имея только `Dockerfile`. Если параметр `build.dockerfile` не задан, Amvera ищет файл в `amvera/Dockerfile`, `Dockerfile`, `docker/Dockerfile`, `deploy/Dockerfile` и `deployment/Dockerfile`. Файл `docker-compose.yml` не поддерживается ([Docker](https://docs.amvera.ru/applications/configuration/docker.html)). Порт для такого приложения тоже задаётся параметром `containerPort` в `amvera.yml`.

```yaml
run:
  containerPort: 3000
```

Если `amvera.yml` рядом с `Dockerfile` нет, приложение должно слушать порт `80`, потому что `containerPort` по умолчанию равен ему.

## Создайте базу данных

Базу создают отдельным проектом, до приложения. В личном кабинете выберите PostgreSQL и нажмите **Создать базу данных** ([PostgreSQL](https://docs.amvera.ru/databases/postgreSQL.html)). Введите имя проекта и выберите тариф. Для базы нужен тариф не ниже **Начальный**, пробного тарифа для баз нет.

{/* TODO: проверить в интерфейсе названия пунктов меню и кнопок */}

Затем заполните поля СУБД.

| Поле | Что вводить |
| --- | --- |
| **Имя создаваемой БД** | Имя базы данных |
| **Имя пользователя** | Логин пользователя базы |
| **Пароль пользователя** | Пароль этого пользователя |
| **Размер кластера СУБД** | Число реплик, для учебного проекта хватит одной |

Имя базы и имя пользователя `postgres` зарезервированы и использоваться не могут. Поля **Активировать Superuser Access** и **Пароль для Superuser** нужны только для доступа суперпользователя, учебному проекту они не требуются. Нажмите **Завершить** и дождитесь статуса «PostgreSQL запущен».

## Создайте приложение

В личном кабинете нажмите **Создать проект** и выберите тип сервиса **Приложение**. Введите имя приложения, выберите тариф и нажмите **Далее** ([быстрый старт](https://docs.amvera.ru/applications/quick-start.html)). Затем откроется этап «Загрузка данных», на нём доступны два способа.

{/* TODO: проверить в интерфейсе весь мастер создания приложения */}

**Через git Amvera.** Адрес репозитория находится на странице **Репозиторий** приложения. Его формат `https://git.amvera.ru/<имя-пользователя>/<имя-проекта>`. Добавьте его как удалённый репозиторий и отправьте код в ветку `master` ([Amvera как основной репозиторий](https://docs.amvera.ru/applications/git/main-origin.html)). Когда Git спросит логин и пароль, введите данные от аккаунта Amvera.

```sh
git remote add amvera https://git.amvera.ru/<имя-пользователя>/<имя-проекта>
git push -u amvera master
```

В документации для этого случая используется имя удалённого репозитория `origin`. Если у вас уже есть `origin` на GitHub, назовите новый, например, `amvera`, как в примере выше.

Сборка запускается после пуша в `master`. Если у вас ветка называется `main`, отправьте её командой `git push amvera main:master`.

{/* TODO: проверить, принимает ли Amvera пуш в main, и работает ли команда main:master */}

**Через GitHub.** Во вкладке **Репозиторий** приложения выберите GitHub, создайте секрет, укажите ветку удалённого репозитория и скопируйте адрес, который покажет Amvera. Затем в репозитории на GitHub добавьте webhook с этим адресом, типом содержимого `application/json` и тем же секретом, событие выберите Push. Для доступа нужен токен GitHub. После этого каждый пуш в репозиторий на GitHub запускает сборку ([подключение GitHub, GitLab, Bitbucket](https://docs.amvera.ru/applications/git/webhooks.html)). Если репозиторий приватный, понадобится классический токен с правом `repo`.

## Передайте приложению строку подключения

Переменные окружения создаются в разделе **Переменные** приложения кнопкой **Добавить переменные или секрет**. В форме два поля, **Название** и **Значение**. Пароль и строку подключения храните секретом. После добавления контейнеры нужно перезапустить, иначе переменные не применятся ([переменные и секреты](https://docs.amvera.ru/applications/configuration/variables.html)). Во время сборки переменные недоступны.

{/* TODO: проверить в интерфейсе, как добавляется секрет и как перезапускаются контейнеры */}

Amvera не создаёт переменные с параметрами базы за вас. В документации нет готовых имён вроде `DATABASE_URL`, поэтому строку подключения вы собираете и записываете сами. Приложение внутри Amvera подключается к базе по внутреннему имени, которое состоит из имени пользователя и имени проекта базы ([PostgreSQL](https://docs.amvera.ru/databases/postgreSQL.html)).

```text
amvera-<имя-пользователя>-cnpg-<имя-проекта-базы>-rw
```

Суффикс `-rw` означает хост для чтения и записи. Точное значение хоста указано на странице **Инфо** проекта базы ([пример на Go](https://docs.amvera.ru/general/examples/go-postgresql.html)). Порт стандартный, `5432`. Приложение и база должны находиться в одном регионе, иначе внутреннее имя не сработает ([сетевое взаимодействие](https://docs.amvera.ru/applications/configuration/network.html)).

Приложения на Node.js, Python и Rails обычно читают одну переменную `DATABASE_URL`.

```text
postgresql://USER:PASSWORD@HOST:5432/DATABASE
```

Java-приложению нужен адрес в формате JDBC. В нём логин и пароль передаются параметрами.

```text
jdbc:postgresql://HOST:5432/DATABASE?user=USER&password=PASSWORD
```

Блог на Javalin читает адрес из переменной `JDBC_DATABASE_URL`. Без неё он запускается на базе H2 в памяти, и данные пропадают при каждом перезапуске.

{/* TODO: проверить в интерфейсе, что при такой строке соединение проходит, и нужен ли параметр sslmode. В примере на Go документации стоит sslmode=disable */}

:::danger[Не добавляйте jdbc: к обычному адресу]
Строка `jdbc:postgresql://USER:PASSWORD@HOST/DATABASE` выглядит правильной, но драйвер PostgreSQL принимает часть до `@` за адрес хоста. Приложение падает с ошибкой `JDBC URL invalid port number`. Если пароль попал в журнал настоящей базы, смените его.
:::

## Запустите деплой

Если вы используете git, пуш в `master` запускает сборку сам. Если файл `amvera.yml` создаёте на последнем шаге мастера, после **Завершить** сборка и запуск начинаются автоматически, а локально нужно выполнить `git pull`, потому что файл появится в репозитории Amvera новым коммитом. Сборка обычно занимает от 5 до 20 минут, в редких случаях дольше ([частые ошибки](https://docs.amvera.ru/general/FAQ/infinite-build-run.html)).

Чтобы приложение открывалось по ссылке, создайте домен. Во вкладке **Домены** нажмите **Добавить доменное имя**, выберите тип подключения HTTPS и тип домена **Бесплатный домен Амвера**, затем нажмите **Применить** ([сетевое взаимодействие](https://docs.amvera.ru/applications/configuration/network.html)). ## Тарифы и ограничения

Бесплатного тарифа у Amvera нет. Страница [тарифов](https://docs.amvera.ru/general/price.html) называет только платные. Стоимость считается поминутно, а списывается раз в час, пока проект запущен, запускается или работает с ошибкой. У остановленного проекта списаний нет, если его файлы укладываются в лимит диска тарифа. Баланс можно пополнить картой на странице [пополнения счёта](https://docs.amvera.ru/general/topup.html). Российские карты поддерживаются без ограничений, иностранные карты должны быть Mastercard, и пополнять ими нужно на сумму от 1000 ₽.

| Тариф | ЦПУ | ОЗУ | SSD | Цена за 30 дней |
| --- | --- | --- | --- | --- |
| Пробный (только приложения) | 0,1 | 100 МБ | 2 ГБ | 170 ₽ |
| Начальный | 0,25 | 500 МБ | 5 ГБ | 290 ₽ |
| Начальный Плюс | 0,5 | 1 ГБ | 7 ГБ | 490 ₽ |

Для базы нужен тариф не ниже «Начальный», то есть от 290 ₽ за 30 дней. Самая дешёвая связка, приложение на «Пробном» тарифе и база на «Начальном», стоит около 460 ₽ за 30 дней. Если держать их включёнными только несколько дней, по почасовой тарификации выйдет меньше. Остановленный проект перестаёт списывать деньги.

Пробного тарифа со 100 МБ памяти может не хватить. JVM для Java-приложения обычно требует больше, поэтому для блога на Javalin ориентируйтесь на «Начальный» тариф с 500 МБ и проверьте это при первом запуске. Приложениям на Node.js и Python 100 МБ может хватить для небольшого учебного проекта, но запас невелик. Если приложение не запускается или отвечает 503, документация советует временно взять более старший тариф, а когда всё заработает, вернуться на подходящий ([частые ошибки 502 и 503](https://docs.amvera.ru/general/FAQ/502-503-error.html)).

Проект, который остановлен вручную или из-за отрицательного баланса, замораживается через 30 дней, и его артефакты удаляются. Следите за балансом, чтобы проект не был удалён.

## Если что-то пошло не так

Сначала откройте журнал сборки и журнал приложения, причина почти всегда написана там. Журналы могут появляться с задержкой от 2 до 5 минут. Если журналов нет совсем, проверьте, что `amvera.yml` или `Dockerfile` лежит в корне репозитория и называется точно так ([частые ошибки](https://docs.amvera.ru/general/FAQ/infinite-build-run.html)).

- **Ошибка 502.** Порт в коде или команде запуска не совпадает с `containerPort`, либо приложение слушает только `127.0.0.1`. Укажите хост `0.0.0.0` и тот же порт, что в `amvera.yml`, затем пересоберите проект.
- **Ошибка 503.** Приложение не запустилось или не хватило ресурсов. Прочитайте журнал и при нехватке памяти временно возьмите тариф старше.
- **Запуск идёт больше 5 минут.** Проверьте, что файл настроек существует и лежит в корне. Скачайте журнал и найдите в нём слово `error`.
- **Нет журналов у приложения на Python.** Добавьте переменную окружения `PYTHONUNBUFFERED` со значением `1`.
- **Приложение не подключается к базе.** Проверьте, что приложение и база в одном регионе, хост взят со страницы **Инфо** базы, а контейнеры перезапущены после добавления переменных.
- **Данные пропадают после перезапуска.** Приложение работает на базе в памяти или в файле. Проверьте, что переменная с адресом PostgreSQL задана и приложение её читает.

Если причину найти не удалось, напишите в поддержку Amvera на support@amvera.ru с именем пользователя и именем проекта.
